# 04 — Node.js 백엔드 및 API 구현 지침

## 목적
Vercel 서버리스 함수로 브라우저 요청을 검증하고 OpenAI 분석을 호출한 뒤, 결과를 검증하여 반환하고 Supabase에 저장한다.

## 엔드포인트
`POST /api/analyze`

요청:
```json
{ "text": "오늘은 좋은 일이 많아서 기분이 좋다." }
```

성공 응답:
```json
{
  "success": true,
  "result": {
    "sentiment": "positive",
    "label": "긍정",
    "confidence": 87,
    "reason": "좋은 일과 기분이 좋다는 긍정적 표현이 중심입니다."
  }
}
```

실패 응답:
```json
{
  "success": false,
  "error": {
    "code": "AI_SERVICE_ERROR",
    "message": "분석 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요."
  }
}
```

## 처리 순서
1. HTTP 메서드가 POST인지 확인한다. 아니면 405.
2. `Content-Type`이 JSON인지 확인한다. 아니면 400.
3. 요청 본문과 `text`가 문자열인지 확인한다.
4. trim 결과가 비어 있으면 400.
5. 원문 길이가 2,000자를 넘으면 413 또는 400으로 거부한다. 프로젝트 내에서는 한 상태 코드로 통일한다.
6. `OPENAI_API_KEY`가 있는지 확인한다. 없으면 서버 설정 오류(500).
7. OpenAI API를 호출한다.
8. AI 결과를 파싱하고 허용된 값인지 검사한다.
9. Supabase에 저장을 시도한다.
10. 저장 실패는 서버 로그에 남기되, 분석 결과는 정상 반환한다.

## 구현 기준
- 파일: `api/analyze.js`
- ESM 형식을 사용한다.
- OpenAI SDK와 Supabase SDK를 서버에서만 import한다.
- 환경변수는 `process.env`에서 읽는다.
- 요청 크기와 텍스트 길이를 제한한다.
- 외부 API 호출 실패와 JSON 파싱 실패를 별도 내부 로그로 구분하되, 사용자에게는 일반화된 메시지를 반환한다.
- 로그에 원문 전체나 비밀키를 남기지 않는다.
- 동일 출처 호출만을 기본으로 하며, 불필요하게 모든 도메인을 허용하는 CORS 설정을 추가하지 않는다.
- 서버리스 함수는 메모리에 상태를 저장하지 않는다.

## HTTP 상태 코드
| 상황 | 코드 |
|---|---:|
| 정상 분석 | 200 |
| 잘못된 메서드 | 405 |
| 입력/JSON 오류 | 400 |
| 입력 길이 초과 | 413 |
| 환경변수 누락 또는 서버 내부 오류 | 500 |
| OpenAI 일시 오류/시간 초과 | 502 또는 503 |

구현 시 오류 상태 코드는 일관되게 적용하고, 프론트엔드가 JSON 오류 형식을 처리하도록 한다.

## 보안
- `OPENAI_API_KEY`는 서버 외부로 절대 전달하지 않는다.
- `SUPABASE_SERVICE_ROLE_KEY`는 서버에서만 사용한다.
- 사용자 입력을 시스템 지침으로 취급하지 않는다. 감성 분석 대상 텍스트 데이터로만 전달한다.
- 프롬프트 인젝션 문장이 포함되어도 모델이 시스템 지침을 바꾸지 않도록 명시한다.
- 오류에 `error.stack`, API 원문 응답, 요청 헤더를 포함하지 않는다.

## 검증 시나리오
- [ ] GET 요청은 405
- [ ] JSON이 아닌 요청은 거부
- [ ] `text` 누락/숫자/배열은 거부
- [ ] 빈 문자열/공백 문자열은 거부
- [ ] 2,001자 입력은 거부
- [ ] 정상 입력은 성공 응답 형식 반환
- [ ] OpenAI 오류 시 안전한 오류 JSON 반환
- [ ] 모델 응답의 sentiment가 허용 목록 밖이면 실패 처리
- [ ] 모델 confidence가 숫자가 아니거나 범위 밖이면 실패 처리
- [ ] API 키가 응답/브라우저 파일에 포함되지 않음
- [ ] DB 저장 장애가 분석 성공 응답을 막지 않음

## 완료 기준
API 계약을 만족하고, 입력 검증·AI 오류 처리·결과 검증·DB 저장을 수행하며, 민감한 정보가 노출되지 않아야 한다.
