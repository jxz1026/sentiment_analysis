# 06 — Supabase 데이터베이스 및 Vercel 배포

## 1. Supabase 테이블
Supabase SQL Editor에서 아래 SQL을 실행한다.

```sql
create table if not exists public.sentiment_analyses (
  id bigint generated by default as identity primary key,
  input_text text not null,
  sentiment text not null check (sentiment in ('positive', 'negative', 'neutral')),
  confidence integer not null check (confidence between 0 and 100),
  reason text not null,
  created_at timestamptz not null default now()
);

create index if not exists sentiment_analyses_created_at_idx
  on public.sentiment_analyses (created_at desc);
```

## 2. 데이터 저장 정책
- 저장 컬럼: `input_text`, `sentiment`, `confidence`, `reason`, `created_at`
- 로그인 기능은 MVP에 없으므로 사용자 ID 컬럼은 만들지 않는다.
- 브라우저에서 직접 insert하지 않는다.
- 서버의 `SUPABASE_SERVICE_ROLE_KEY`를 이용해 서버에서만 insert한다.
- 저장 실패 시 분석 결과는 사용자에게 정상 반환한다. 서버 로그로만 저장 실패를 확인한다.
- 입력 문장이 저장된다는 점을 UI에 고지한다.

## 3. Supabase 보안 확인
- `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 Vercel 서버 환경변수에 등록한다.
- Service Role Key를 브라우저 JavaScript에 넣지 않는다.
- RLS를 활성화한다. 서버의 Service Role Key는 RLS를 우회하므로 서버 코드에서만 안전하게 사용해야 한다.
- 공개 익명 권한에 테이블 SELECT/INSERT 권한을 부여하지 않는다.
- 실제 운영 전에는 보존 기간, 삭제 요청 처리, 접근 로그 정책을 별도로 결정한다.

## 4. Vercel 배포 순서
1. 프로젝트를 Git 저장소에 올린다.
2. `.env`와 실제 비밀키가 Git에 포함되지 않았는지 확인한다.
3. Vercel에서 새 프로젝트를 만들고 저장소를 연결한다.
4. Framework Preset은 정적 사이트/Other에 맞게 설정한다.
5. Root Directory는 프로젝트 루트로 지정한다.
6. 환경변수 4개를 등록한다.
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
7. Production뿐 아니라 Preview 환경에서 테스트할 계획이라면 해당 환경에도 필요한 변수를 등록한다.
8. 배포를 실행한다.
9. 배포 URL에서 화면, API, DB 저장을 확인한다.

## 5. 운영 전 필수 점검
- [ ] OpenAI 키가 브라우저 번들에 노출되지 않음
- [ ] Supabase Service Role Key가 브라우저 번들에 노출되지 않음
- [ ] Vercel 환경변수가 올바른 환경에 등록됨
- [ ] `POST /api/analyze`가 배포 URL에서 동작
- [ ] Supabase 테이블에 분석 기록이 저장됨
- [ ] DB 장애 시에도 분석 결과가 표시됨
- [ ] 브라우저 응답에 내부 오류·키가 포함되지 않음
- [ ] 모바일 화면에서 정상 사용 가능
- [ ] 테스트용 개인정보·민감한 문장을 운영 DB에 불필요하게 남기지 않음

## 6. 완료 기준
배포된 URL에서 사용자가 문장을 입력해 분석 결과를 받고, 정상 분석 건이 Supabase에 저장되는 것을 확인해야 배포 완료로 선언한다.
